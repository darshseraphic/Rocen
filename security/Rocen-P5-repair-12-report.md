## Source changes

Security-sensitive changes in this repair:

- `lib/core/master_key_production_service.dart`: preserves the paired pinned snapshot through recovery; validates/rechecks both authority files; checks exact semantic wrapper identity; delays recovery/association publication markers until shared-state work and final paired validation complete; keeps expected-current local writes and fences.
- `lib/core/master_key_local_store.dart`: documents the precise, point-in-time `published` marker contract.
- `lib/core/github_backup_service.dart`: scopes the pre-decode size cap to reserved authority paths, preserving generic Contents compatibility.
- `test/authority_recovery_ordering_test.dart`, `test/support/fake_github_remote.dart`: exercise the ownedLocal create races, exact wrapper versus same-MK/different-wrapper behavior, missing-state bootstrap, and malformed post-create state.
- `test/github_authority_raw_json_test.dart`: exercises oversized generic JSON through the actual Contents decoder.
- `test/widget_test.dart`: fixes the fake-async Hive stall and tests default-deny on unsupported capture platforms without changing production policy.

The full exact source/test file list changed relative to the workspace baseline is in `repair12-validation/source-changed-files.txt`. ## Remaining limitations and decisions

- GitHub and Hive do not share a transaction. A remote commit after the last paired freshness read can race with local persistence.
- `lockSync()` cannot retroactively cancel an HTTP request or Hive write already started; it blocks later protected effects only at checked boundaries.
- Stage 6 encrypted application-data persistence remains out of scope and fail-closed.
- Same-isolate Dart code is not sandboxed against deliberately hostile in-process code. A security/product owner decision is still required on the intended activation trust boundary.
- Android native enforcement lacks target-device screenshot/recording evidence; native enforcement remains **UNVERIFIED**. iOS and other unsupported platforms remain fail-closed.
- Dart immutable `String` values and inaccessible runtime/library copies are not claimed physically erased.
- Some tests that require an unlocked session cannot reach their assertions on this Windows host because production screen policy correctly denies activation. They must be exercised on a supported target or via a narrowly scoped, non-public test arrangement; production policy must not be weakened.
- Stage 5 remains **NOT APPROVED**. The full-suite gate failed, release build failed before app compilation, the activation trust boundary and native enforcement are open, and several integration/schema/branch requirements remain incomplete.
